# NearPill data and order inventory

Reviewed 13 October 2026. Scope: Flutter customer app, web operations portal, Node/MySQL backend. Real payments are planned but not implemented. Contact supplied by the team: **nearpillemail@gmail.com**. The legal operator name, address and production hosting are unconfirmed.

| Registration and sign-in | Name, email, password; create account and authenticate | MySQL `users`; NearPill server; mobile tokens in secure storage | Signup/reset use salted Argon2id. The read-only local audit found five plaintext records; dormant records still need migration/reset. Database, audit, backup and provider-log retention periods are not configured. Mobile debug HTTP logging omits bodies and headers; existing operational logs still need review. |

**Order outcomes:** customers can cancel their own nonterminal orders before ready-for-pickup/completed and before expiry. Stock is restored on supported cancellation paths. The scheduled expiry routine expires unclaimed orders after three days and restores stock; it does not refund money. Admin status edits and customer cancellations may change local paid records to `refunded`; scheduled expiry leaves payment records unchanged. These paths need one approved commercial policy before live payments.

**Claims:** fabricated API licence/manufacturer defaults, mobile ratings/distances, sample stock fallback, live geo-search/upload claims, unsupported verification badge and refund timeline were removed or corrected. Browser branch fixtures remain explicitly labelled demo data. No actual pharmacy licence, medicine registration, image licence or business registration was verified.

**Retention and rights:** no automatic database deletion exists. Mobile tokens persist until cleared; server session maps reset on restart and have no time-based expiry. Browser demo selection persists until logout/site-data removal. Contact the supplied email for requests; identity checks, request handling and approved retention periods still need an operational procedure. See the [audit](readiness-audit.md) and [shared prelaunch policies](../web/policies.json).
